The geometric ladder: seven tests of computing by settling.

Can a small network that computes by settling into a low-energy shape, instead of a large model, do real work, improve itself, share safely, defend itself and fit on a small device? Seven builds, one per rung. Each wrote down its claims and bars before any code, froze its results by hash, read its held-out data once, and kept every failure. This page reads each rung's committed verdicts live.

Watch it settle

A settling cell, running in your tab on a digit from Rung 1's held-out file. The settle flips one bit at a time, only when the flip raises the fit, until nothing more can flip. Watch the digit change and the reading change with it.

Then try a scrambled digit on each cell. On Rung 1's cell almost every scrambled digit settles with zero fit and is rejected. Switch to Rung 4's evolved node, the shape Rungs 5 and 7 defended: its wells are wider, and many more scrambled digits settle into one with a real fit, so a fit-check alone lets them through. That is the failure Rungs 5 and 7 recorded. (Rung 4's node was grown on MNIST digits; here it reads Rung 1's digits, which are made in a similar way: a 32 by 32 bitmap counted in 4 by 4 blocks.)

    Words on this page

    Held, failed, not testedEach claim had a bar written down before any code. Held: the measured number met its bar. Failed: it did not, and the claim is kept on the record. Not tested: it could not be run here (only Rung 7's real-chip claim).
    SettleTo read an input, the cell flips its bits one at a time, each flip only if it makes the input match the cell's stored patterns better, until no flip helps. The class of the patterns it ends up nearest is the answer.
    Fuzzy reader, exact codeThe fuzzy reader is the cell: it reads messy handwriting and can be wrong. Exact code is ordinary tested logic, such as a check digit, that is either right or wrong and never guesses (Rung 3).
    Cell, shapeThe cell is the small reader; its shape is what it reads with: a couple of hundred stored digit patterns and two numbers that set how widely each pattern pulls.
    FitHow strongly the settled state matches the stored patterns. Zero fit means it matches nothing.
    One-step readReading the same input with the same shape without settling: just which stored patterns it is nearest as it arrives. The fair baseline for settling.
    Model-freeNo neural network is trained. Code proposes small changes and keeps one only if it wins a fresh exam.
    Held-outData kept aside and read once, after everything is frozen, so the result cannot be tuned to it.
    SealCommitting the claims (seal 1), then the frozen results (seal 2), to the public record before the held-out data is read.
    Mutation gateA tool (witness) that breaks the code in small ways, one at a time, and checks the tests catch every break. Clean means every one was caught, with none excused.

    How it works

    1. Seal 1. Each rung commits its claims and their bars alone, before any code.
    2. Build and tune on training data only. A disclosed amendment is allowed before the held-out read, with the bars unchanged.
    3. Seal 2. The final shapes, code and records are frozen by SHA-256. The held-out reader refuses to run unless seal 2 names them.
    4. Read once. The held-out data is read one time; the record is committed; every claim is judged against its bar.
    5. Gate and re-derive. Every kernel faces a mutation gate (witness v0.6) that must catch every mutant with nothing baselined, and every record re-derives byte for byte on GitHub's runner and in the browser.

    Adoption

    For a business

    The parts that held are the trust machinery: signed sharing checked on raw bytes, a receiver's own exam before any change, exact code behind a fuzzy reader, and a fail-safe layer that never stops the device. Those carry over to any fleet of sites or devices.

    For engineering

    Each rung is a small, pinned, re-derivable repository: seal, build, freeze, read once, gate. Fork one rung and run its --check to see the whole method.

    For research

    The failures are the finding. Settling, as a computation, never reliably beat reading the same shape in one step. That is published, with the code to re-run it.

    A pilot, step by step

    1. Pick one task you do by hand that has a right answer you can check later.
    2. Write down the bars it must meet before anything is built, and seal them.
    3. Build on your past data only; keep a held-out slice untouched.
    4. Freeze it, then judge it once on the held-out slice. The fee is due only if it beat your current way.
    5. Run it beside your current process, deciding nothing, before it is trusted with anything.

    What the rungs run on: Node.js 20 or a current browser. No GPU, no cloud service, no model download.

    White paper: what seven sealed builds say about computing by settling

    The question. Could small networks that compute by settling replace large models for real tasks, and carry their own trust: self-improvement without a model, safe sharing, defence and a small-device footprint?

    The method. Seven builds, each on public handwriting data (UCI optdigits, UCI Semeion, MNIST), each with its claims sealed before code, its results frozen by hash, its held-out data read once, every failure kept, every kernel mutation-gated and every record re-derived on GitHub's runner.

      The case for the board

      Questions buyers ask

      Does settling beat a normal model?Not on this evidence. On both rungs that tested it, settling never reliably beat reading the same shape in one step (on Rung 1 the one-step read was better clean and noisy; on Rung 2 it was better clean, and under noise the two were within error), and a nearest-neighbour baseline beat the settling cell on Rung 1. That is published on the rungs' pages.
      Then what is it good for?The machinery around it held: signed sharing, a receiver's own exam, exact code behind a fuzzy reader, a fail-safe layer. Those apply to whatever reader you use.
      How would we test it on our own data?Seal the bars, build on your training data, freeze, and judge once on held-out data. The fee is due only if it beat your current way.
      Has it run on real hardware?Not yet. Rung 7 ran on an emulator held to microcontroller rules, and says so on every number. The next step is running the same record on a Raspberry Pi; no date is promised until a board is in hand. Power use is not measured.
      Where does our data go?Nowhere. Every rung runs on your own machine or in your browser tab, and each page's security policy blocks connections to anywhere but its own files. Nothing is sent to us. As with any in-house tool, your data-protection duties stay with you.
      Who has done this for a client? Is it certified?No client case study is published yet, and no certification is claimed. Every record re-derives from pinned files.
